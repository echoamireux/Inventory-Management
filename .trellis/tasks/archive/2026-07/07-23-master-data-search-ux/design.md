# 技术设计：主数据管理页面与全局搜索体验改造

## 1. 边界与总体方案

本任务只改小程序搜索交互、主数据页面信息架构和搜索结果相关性，不改变库存核心模型、权限模型、集合名称或导入事务协议。现有未提交变更全部视为基线，不回滚、不覆盖。

搜索分为三类：

1. 列表浏览：输入停止约 400ms 自动刷新，回车立即执行，清空恢复列表。
2. 选择器：输入后显示候选，必须点击候选写入已选择实体；不得自动选择第一条。
3. 导航/高成本查询：首页导航搜索改为显式执行；项目用料保留防抖但合并重复请求，必要时显示查询状态。

## 2. 搜索协议

### 规范化

在小程序端和云函数端分别维护同构的搜索工具：首尾空格、大小写、全角/半角、横杠和连续空格统一；原始输入只用于展示。正则查询继续转义用户输入，不启用默认错别字猜测或拼音猜测。

### 匹配等级

共享评分函数接收记录、关键词和字段配置，返回 `score`、`match_reason`、`match_field`：

- 1000：规范化产品代码完全匹配；
- 950：规范化测试料型号完全匹配；
- 800：产品代码或型号前缀匹配；
- 650：物料名称完全匹配；
- 500：产品代码或型号包含匹配；
- 300：供应商、子类别、规格、批号、库位等辅助字段包含匹配；
- 0：不匹配。

同分时使用业务稳定字段兜底，例如产品代码、型号、`_id`。`J-9` 只产生候选排序，不自动改写成 `J-900`。

### API 兼容

现有列表 API 保留原有输入字段和业务筛选；搜索关键词非空时，返回项可增加 `match_score`、`match_reason`、`match_field`，旧调用方忽略这些附加字段。物料列表增加“全局搜索/包含历史状态”的显式参数，普通在用/已归档浏览仍使用原状态筛选；测试料型号通过已有 `includeDisabled` 控制历史结果。

由于微信云数据库没有通用相关性排序，服务端在有关键词时收集有界候选、去重、评分、稳定排序后分页；超过候选上限返回可识别的“结果过多，请继续输入”状态。日志和项目报表继续按时间倒序，搜索只作为过滤，不打乱审计时间线；导出继续使用稳定业务排序。

## 3. 主数据页面

`material-list` 作为“主数据管理”入口：

- 一级模式为“物料主数据”和“测试料型号库”；
- 物料主数据内部使用“在用/已归档”状态筛选；“活跃物料”改为“在用物料”或直接使用“在用”；
- 测试料型号模式直接显示维护列表、数量、导入和新增操作，不再出现“维护型号库”中间按钮；现有独立导入/新增工作流继续复用；
- `material-list` 的测试料型号模式作为直接浏览入口；现有 `test-material-identity-manage` 保留为新增/导入等变更工作流页面，由测试料模式的操作按钮直接进入，不再作为查看列表前的中间入口，避免复制型号维护业务校验。
- 页面顶部保留一个全局搜索框。无关键词时按当前模式浏览；有关键词时显示“物料主数据”和“测试料型号”两组结果，测试料结果显示所属物料和状态；历史结果默认可见但标记归档/停用，不可用于新业务选择；
- 联想结果卡片显示匹配原因，点击物料或型号进入对应维护/详情路径。

## 4. 页面触发改造

- 首页顶部搜索：删除输入停顿后自动导航；保留输入值，回车/搜索键导航，若展示建议则点击建议导航。
- 测试料型号维护列表：补齐与其他列表相同的 400ms 防抖自动刷新、回车立即刷新和清空恢复。
- 库存、物料目录、日志、标签历史、项目用料：统一输入取值、定时器清理、请求编号保护和清空行为；不改变日志时间线或报表筛选语义。
- 物料选择、快捷领料、预打印、入库和新增测试料父级物料：保留自动联想和显式点击选择，不把列表搜索的自动刷新误用于选择提交。
- 人员管理继续本地即时过滤；保留当前规模下的简单实现，并为后续服务端分页留出边界，不在本任务引入新的人员查询 API。

## 5. 兼容、发布与回滚

- 不新增数据库集合；如新增共享云端搜索工具，执行现有共享同步脚本并部署受影响云函数。
- 保持原有调用方可传 `searchVal`/`keyword`，不改变导出文件筛选结果，只统一搜索词规范化。
- 若相关性排序在真实数据量下造成查询超时，可回滚为原业务排序，同时保留触发和页面结构改造；候选上限、匹配级别均为常量，便于调整。
