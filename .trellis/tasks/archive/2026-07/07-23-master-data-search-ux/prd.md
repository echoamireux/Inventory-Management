# 主数据管理页面与全局搜索体验改造

## Goal

统一库存管理小程序的搜索交互和主数据管理信息架构，让用户能用一次搜索找到物料主数据或测试料型号，并在不误跳转、不误选物料的前提下完成查询和维护。

## Requirements

- 列表型页面采用防抖即时搜索，回车/搜索键作为立即执行方式，清空后恢复当前筛选下的完整列表。
- 首页顶部搜索不得因输入停顿自动跳转；应通过搜索键、回车或点击建议显式进入库存搜索结果。
- “搜索并选择”场景（快捷领料、入库、预打印、新增测试料父级物料）继续自动显示候选，但必须由用户点击具体候选完成选择。
- 主数据页面改为“主数据管理”下的“物料主数据”和“测试料型号库”两个一级入口；在用/已归档只作为物料主数据的状态筛选，测试料型号库直接进入维护列表。
- 主数据管理保留一个全局搜索入口；输入关键词时同时返回物料主数据和测试料型号结果，结果按实体分组并显示父子关系。
- 全局搜索有关键词时默认分组显示全部结果；无关键词时按当前一级模式浏览，不要求用户为了确认另一类结果而反复切换页签。
- 全局搜索默认包含历史物料和停用型号，但结果明确标注状态，历史记录不可被新入库、领料或预打印选择器使用。
- 搜索词统一做首尾空格、大小写、全角/半角、横杠和多余空格规范化；不得默认进行可能造成误选的错别字猜测。
- 搜索匹配优先级为：规范化后的精确产品代码/型号、代码/型号前缀、名称精确匹配、代码/型号包含、供应商/子类别/规格等辅助字段包含。
- 搜索结果应显示匹配原因，并使用稳定的相关性排序；无关键词时保留各页面原有业务排序。
- 保持现有库存、日志、报表、标签和批量导入业务规则，不改变权限和数据模型；仅调整搜索触发、结果组织、排序和主数据页面导航。

## Acceptance Criteria

- [ ] 首页输入关键词停顿超过 500ms 不会自动离开首页；点击搜索键、按回车或点击建议后才进入库存结果页。
- [ ] 库存列表、物料目录、物料主数据、管理日志和项目用料页面在输入停止后自动刷新，回车可立即刷新，清空可恢复列表。
- [ ] 测试料型号维护列表改为防抖自动刷新，同时保留回车立即查询。
- [ ] 主数据页面一次输入 `J-999`、`ABC-200` 或物料名称时，能在同一搜索结果中看到对应物料和测试料型号；测试料型号结果显示所属物料。
- [ ] 精确匹配优先于前缀匹配，前缀匹配优先于普通包含匹配；同一排序级别以稳定字段兜底，不因分页重复或跳动。
- [ ] `J-9` 只展示候选，不自动替换或自动选择 `J-900`；入库、领料和预打印必须点击具体候选。
- [ ] 预打印、快捷领料、入库和新增测试料父级物料的联想搜索仍能在输入后显示候选，且旧的选择校验不回退。
- [ ] 项目用料等高成本查询不会因每个字符产生重复并发请求；搜索和筛选结果保持一致。
- [ ] 现有测试全部通过，并新增覆盖首页导航、统一主数据搜索、相关性排序和各类触发模式的测试。

## Notes

- 当前工作区已有大量未提交变更，本任务只能在其基础上追加，不得回滚或覆盖既有修改。
- 当前云函数使用大小写不敏感的转义包含正则；本任务需要增加相关性排序，但不引入外部搜索服务。
- 页面重构应优先复用现有 `manageMaterial`、`manageTestMaterialIdentity` 和搜索工具，不创建新的数据库集合。
- 用户已授权“按照建议修改”；未返回单独的结果布局/状态范围选择，因此采用推荐默认：分组显示全部结果，历史结果可搜但带状态。
