# 测试料型号选择器云端分页搜索

## Goal

将测试料型号选择器从一次加载100条后的本地筛选，改为按产品代码和关键词云端分页搜索，覆盖标签打印、单个入库、批量入库和维护列表。

## Requirements

- 标签打印、单个入库、批量入库中的测试料原厂型号弹窗，不能只加载前 100 条后在本地筛选。
- 弹窗必须按当前测试料产品代码、当前关键词、分页参数调用 `manageTestMaterialIdentity` 云函数。
- 空关键词时加载当前产品代码下第一页型号；输入关键词时重新从第一页搜索；上拉加载下一页。
- 搜索结果为空时显示明确空状态；结果过多时显示后端 `searchMessage`，提醒继续输入关键词。
- 选择器仍必须点击具体型号，不允许自动选择第一条。
- 产品代码第一层保持现有“前缀 + 数字 / 精确代码查找”逻辑，不恢复按名称搜索。
- 测试料型号维护列表不能永久只展示 100 条，必须支持分页或上拉加载。
- 不新增集合；不改变测试料主数据“代码壳”和型号库“真实身份”的数据模型。

## Acceptance Criteria

- [ ] `J-999` 下存在超过 100 个型号时，输入能搜索到第 101 条以后的匹配型号。
- [ ] 标签打印测试料型号弹窗支持关键词云端搜索、清空恢复、上拉加载。
- [ ] 单个入库测试料型号弹窗支持关键词云端搜索、清空恢复、上拉加载。
- [ ] 批量入库测试料型号弹窗支持关键词云端搜索、清空恢复、上拉加载。
- [ ] 测试料型号维护列表支持分页加载，不再一次性固定 100 条。
- [ ] 旧请求返回晚于新请求时，不得覆盖当前弹窗结果。
- [ ] 空结果和结果过多都有清晰提示。
- [ ] 现有测试通过，并新增/更新覆盖远程搜索契约的测试。

## Notes

- 用户明确未来单个测试料代码下型号会超过 100 个；这是必须修复的真实规模假设。
- 产品代码总数超过 100 不是本任务核心风险，因为标签打印和入库第一层按精确产品代码查询。
