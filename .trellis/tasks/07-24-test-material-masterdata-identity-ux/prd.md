# 测试料主数据与型号库体验优化

## Goal

让“物料主数据”和“测试料型号库”的职责在界面、导入模板和后端数据合同上保持一致，减少管理员维护测试料时的误解：

- 物料主数据只维护测试料代码壳、类别、子类别、单位和规格，不再让用户在测试料主数据页填写真实供应商/原厂型号。
- 测试料型号库负责维护测试料的真实原厂型号，并允许记录一个选填供应商作为来源/默认供应商。
- 外部点击“新增测试料型号”时直接进入独立新增页，体验对齐物料主数据的“新增物料”页面，不让用户进入列表后再点一次新增。
- 测试料型号导入模板、前端预览、云函数创建、列表展示、搜索和测试保持同一套字段协议。

## Background and Confirmed Facts

- 当前主数据新增/编辑页在测试料开关打开时仍显示“供应商信息”分组，包含“供应商”和“原厂型号”输入，并提示“测试料真实原厂型号请在入库或标签预打印时填写；这里可留空，用于 J-999/M-999 这类统一测试代码。”证据：`miniprogram/pages/admin/material-edit.wxml:88-109`。
- 当前主数据提交会把 `supplier` 和 `supplier_model` 一并提交给 `manageMaterial`；后端 `MATERIAL_EDITABLE_FIELDS` 和 `buildGovernedMaterialMasterFields()` 仍接收这两个字段。证据：`miniprogram/pages/admin/material-edit.js:588-653`、`cloudfunctions/manageMaterial/index.js:34-48`、`cloudfunctions/manageMaterial/index.js:206-216`。
- 当前从“主数据管理 > 测试料型号库 > 新增”进入二级页时带 `action=create`，二级页 `onLoad()` 会在加载列表后自动调用 `onCreateIdentity()` 弹出底部弹窗。证据：`miniprogram/pages/admin/material-list.js:722-724`、`miniprogram/pages/admin/test-material-identity-manage/index.js:74-78`。
- 当前测试料型号新增弹窗只有“测试料主数据”和“原厂型号”，没有供应商字段。证据：`miniprogram/pages/admin/test-material-identity-manage/index.wxml:60-107`。
- 用户已明确反馈：测试料型号库应和物料主数据一样，外层展示列表，点击“新增”后直接进入输入页面；新增页直接维护测试料产品代码、原厂型号和供应商（选填），不要进入列表后再点一次，也不要用底部弹窗作为主要新增形态。
- 用户进一步确认：测试料代码壳数量很少，新增型号页的测试料产品代码应优先用下拉选择，而不是手输或搜索选择。
- 当前系统数据库为空，本任务不需要为历史测试料主数据、旧两列模板或旧型号记录做迁移/兼容。
- 当前测试料型号库模板只有两列：`测试料产品代码*`、`原厂型号*`；前端导入也强校验同样两列表头。证据：`cloudfunctions/exportTestMaterialIdentityTemplate/identity-template-workbook.js:13-17`、`miniprogram/pages/admin/test-material-identity-import/index.js:19-22`。
- 当前测试料型号库导出模板的 A 列已经使用 Excel 下拉校验，来源为系统当前已启用的测试料主数据；后续新增供应商列时应保留这一机制。证据：`cloudfunctions/exportTestMaterialIdentityTemplate/identity-template-workbook.js:120-172`。
- 当前 `test_material_identities` 记录规范化包含 `product_code`、`supplier_model`、`supplier_model_key`、`identity_key`、`status`，不持久化 `supplier`。证据：`cloudfunctions/manageTestMaterialIdentity/test-material-identities.js:46-68`、`cloudfunctions/manageTestMaterialIdentity/index.js:221-235`。
- 搜索合同要求前后端关键词规范化同构、搜索结果可带 `match_score/match_reason/match_field`，同分排序稳定；测试料型号列表全局搜索可包含停用记录。证据：`.trellis/spec/frontend/search-ux-contracts.md`。

## Requirements

### R1. 测试料主数据页面收敛字段职责

- 在 `miniprogram/pages/admin/material-edit` 中，测试料开关打开后，不再展示可编辑的“供应商”和“原厂型号”输入。
- 测试料状态下的说明文案应明确：真实原厂型号和可选供应商在“测试料型号库”维护；入库和预打印只能选择已启用型号。
- 正式物料仍保留“供应商信息”分组，供应商和原厂型号仍为选填。
- 新建或编辑测试料主数据时，前端提交给 `manageMaterial` 的 `supplier` 和 `supplier_model` 应为空，避免继续把真实型号写回测试料代码壳。
- 物料批量导入模板中的主数据供应商/原厂型号仍保留给正式物料；测试料导入行若填写这两个字段，不应让用户误以为它们会成为测试料真实身份，文案和测试需同步。

### R2. 测试料型号库新增/编辑体验统一

- 新增测试料型号应使用独立页面，例如 `test-material-identity-edit`，不再使用列表页底部弹窗作为主新增入口。
- 外层“新增”按钮直接进入新增页；测试料型号库列表页内的“新增”按钮也进入同一个新增页。
- 新增页结构对齐物料主数据新增页：清晰标题、基础信息表单、底部/页面提交按钮，而不是进入列表后再弹窗。
- 测试料型号库列表页只负责浏览、搜索、停用/启用和进入新增/导入入口。
- 批量导入继续进入独立导入页，不把导入功能塞回列表页。
- 新增测试料型号页直接提供“测试料产品代码”下拉选择，选项只来自已启用测试料主数据，并展示产品代码、物料名称和类别。
- 新增页不新增“材料类别/代码前缀”选择器，也不让用户手输未建档代码；如果没有可选测试料代码，应提示先维护测试料主数据代码壳。

### R3. 测试料型号供应商选填字段

- `test_material_identities` 在现有集合内增加 `supplier` 选填字段，不新增集合。
- `supplier` 是来源/默认供应商元数据，不参与唯一身份判断；唯一身份仍为 `category + product_code + supplier_model_key`。
- 新增页增加“供应商（选填）”输入；列表卡片有供应商时展示，无供应商时不占用主视觉。
- 搜索测试料型号时，供应商作为辅助字段参与包含匹配，匹配原因仍遵循现有搜索评分体系。
- 审计事件应记录供应商字段，便于追溯谁创建了哪个来源供应商的测试料型号。

### R4. 测试料型号批量导入模板和协议

- 导出模板新增第三列 `供应商（选填）`。
- 模板帮助页、内联提示、简易结构、打开模板后的弹窗文案同步说明供应商是选填。
- 前端解析和预览识别第三列供应商，导入 payload 传给后端。
- 后端 `batchCreate` 保存供应商字段，导入结果至少保留行号、产品代码、原厂型号和错误信息；供应商不改变重复判断。
- 后端允许供应商缺省；前端和导入解析直接按最新版三列表头实现，不需要兼容旧两列模板；Excel A 列继续使用系统当前已启用测试料产品代码下拉。

### R5. 选择器联动

- 测试料型号选择器动作项应携带 `supplier`，入库、批量入库和标签预打印选择型号后可用该供应商作为默认值。
- 如果用户已在入库/模板中明确填写供应商，系统不应强行用型号库供应商覆盖用户输入；供应商字段只是默认值，不是库存身份键。
- 补打标签、报表和出库仍以库存快照为准，不因型号库供应商后续变化而改写已发生业务数据。

## Out of Scope

- 不新增数据库集合。
- 不把 `supplier` 加入 `test_material_identities.identity_key` 或库存身份键。
- 不改变测试料必须选择已启用原厂型号的规则。
- 不做历史数据迁移、旧模板兼容或旧型号记录清洗；当前数据库为空，直接按新规则落地。
- 不改变库存批量入库的 10 行分批事务协议。

## Acceptance Criteria

- [ ] 打开新增/编辑物料页，正式物料仍显示“供应商信息”；切换为测试料后不再出现供应商/原厂型号输入，并出现指向测试料型号库的准确说明。
- [ ] 创建或保存测试料主数据时，提交 payload 中 `supplier` 和 `supplier_model` 被清空；正式物料不受影响。
- [ ] 从主数据管理页点击“测试料型号库 > 新增”后，直接进入测试料型号新增页，不出现“进列表后再点新增”的二次操作。
- [ ] 从测试料型号库列表页点击“新增”也进入同一个新增页。
- [ ] 新增测试料型号页通过下拉选择测试料产品代码，选中后自动带出所属物料名称和类别；不出现类别或代码前缀选择器。
- [ ] 没有已启用测试料主数据时，新增页给出明确空状态，提示先维护测试料主数据代码壳，不允许提交。
- [ ] 新增测试料型号可填写供应商（选填），后端保存到 `test_material_identities.supplier`，审计 detail/after 可追溯。
- [ ] 测试料型号列表展示供应商，搜索供应商可以命中记录，匹配为辅助字段匹配。
- [ ] 测试料型号导出模板包含 `测试料产品代码* / 原厂型号* / 供应商（选填）` 三列；A 列继续使用系统当前已启用测试料主数据生成 Excel 下拉；前端上传预览和后端批量创建都能识别供应商列。
- [ ] 同一产品代码 + 原厂型号重复时仍被拦截；不同供应商不允许绕过同一型号重复检查。
- [ ] 入库、批量入库和标签预打印选择测试料型号后，供应商可作为默认值带入；补打和导出继续使用库存快照。
- [ ] 相关测试更新后通过目标测试、`git diff --check`，最终全量 `npm test` 不回退。
